# App harness source audit — 2026-09-28

Source-only review during kernel memory pressure 2. No build, compiler, app, GPU, browser, network, install or test was run. This report covers all 40 tracked app test/scene files. `BatchExportProbe.swift` and its later timer correction are still unbuilt at this checkpoint. Findings are source traces, not observed runtime failures.

| Rank | Finding, trigger and consequence | Smallest correction / missing proof |
|---|---|---|
| **P2 — a small analysis image stages the whole RAW in memory** | `Screenshot.developedCGImage(fitting:)` reads every pixel of the full output into `Float16` at `app/Screenshot+Measure.swift:74-82`, makes another full-frame byte array at `:82-90`, then copies it into `Data` at `:96`. Only then does CoreGraphics draw the requested small image (`:105-113`). This is a shipping path: subject analysis calls it at `app/Engine+Render.swift:80-86`, face detection requests a 1024-pixel long edge at `app/AgentFaces.swift:44-53`, and agent proxy inspection calls it at `app/AgentInspect.swift:23-31`. For a 42 MP narrow RGBA frame, the arrays are approximately 336 MB (`Float16`), 168 MB (`UInt8`), and 168 MB (`Data`) in decimal units before image/provider allocations. The calls are on the main actor. This can turn a small analysis request into a large peak allocation and pause. These are source-derived payload sizes, **not measured RSS**. This is separate from the settled native histogram's ~840 MB source-derived buffers in `2026-09-28-canvas-geometry-audit.md`: different implementation and trigger; the two estimates must not be summed into one measured peak. | Downscale on the GPU or into a bounded intermediate before readback; keep the full-size path only for genuinely full-size requests. Measure peak footprint and latency on a 42 MP frame when memory pressure permits. Existing reduced-fixture GPU memory numbers do not include this host staging. |
| **P2 — stateful repro scripts alter persistent sample siblings** | The runner's `open` keeps the caller's photo path (`app/Scenario+Frame.swift:21-25`), `snapshot clear` silently removes that photo's versions file (`:223-225`), `matte` writes a PNG beside it (`app/Scenario+Mask.swift:105-109,586`), and `save` writes its sidecar (`app/Scenario+Frame.swift:242-251`). Both `repro/snapshot-keeps-its-matte.txt:26-30,42,57` and `repro/snapshot-survives-a-reopen.txt:19-23,46,57` use `samples/_PIC8220.ARW` directly. A run can erase existing version history, replace a sidecar and leave matte files; a failed or interrupted run can leave the fixture changed for later checks. The sample RAW is a symlink, while these companion paths are under `samples/`; no claim is made that the linked original RAW is modified. | Run stateful scenarios on a temporary copy, as `Scenario.checkDesktopWorkflow` and `BatchExportProbe` already do, with companion-file cleanup. Verify repeated runs from the same fixture bytes and inspect sibling-file diffs. |
| **P2 — an expected refusal accepts unrelated analysis failures** | `app/Scenario+Mask.swift:223-242` implements `refuses sky` by treating *any* exception from `SubjectMatte.generateBlocking` as success. `repro/sky-mask.txt:45` invokes it to prove the sky detector rejects a no-sky photograph, but `SubjectMatte.Failure` also has `couldNotRender` and `vision` (`app/SubjectMatte.swift:65-80`). Broken render/readback or Vision execution therefore makes that current scenario's refusal assertion green for the wrong reason. | Accept only `.nothingFound` for the expected refusal; propagate all other errors as scenario failures. A controlled render/readback failure and a genuine no-sky fixture distinguish the branches. |
| **P3 — `maskcheck` may pass with no cells on one side** | `app/Scenario+Mask.swift:642-662` classifies a grid into fully covered, clear and falloff cells; `:690-718` declares success whenever no *classified* cell violates its comparison. It never requires either `inside` or `outside` to contain a cell. A fully covered, empty, or coarse/off-frame mask can print “every cell … (0 cells)” and award both checks without testing the missing side. Current scripts use this assertion repeatedly, including `repro/mask-alignment.txt:49-55` and `repro/mask-follows-the-frame.txt:60-63`. | Require nonempty covered and clear sets, or make the script explicitly choose a one-sided assertion. A mask that covers zero grid cells should fail the two-sided command. |
| **P3 — the batch heartbeat number had the wrong origin; source-corrected, unbuilt** | The original `app/BatchExportProbe.swift:95,111,118` started its timer before `runInteractive` but labeled the result “heartbeat after first job,” including preflight and job one's decode/render/export. The boolean cancellation oracle was valid. A source edit during this audit moves the start into `progress(done == 1)` immediately before timer scheduling and labels the result “post-job-one timer scheduling to main-actor heartbeat” (`app/BatchExportProbe.swift:102-118`). The historical ~4.735916 ms can only be described as session-start→timer-before-job-two; it was not post-job event latency. | Run the corrected probe after memory pressure lifts. Measure per-photo main-thread blocking separately; the 64×64 fixture cannot establish full-size responsiveness. |
| **P3 — a `shot` can fail silently** | `app/Scenario+Report.swift:291-293` accepts the `shot` verb without checking the result. `Screenshot.writeCanvas` returns `Void` and silently returns on absent texture, image conversion failure or failed disk write (`app/Screenshot+Measure.swift:231-237`). A scenario with another passing assertion can exit 0 although its requested PNG was never written. The current `repro/*.txt` corpus does not invoke `shot`, so this is a dormant oracle defect, not a claim that a current gate is green on it. | Have `writeCanvas` return success (or throw) and make `shot` fail when it cannot write. A single invalid destination exercises the refusal. |
| **P3 — the sky screenshot can render without its sky mask** | In `app/Screenshot+Scenes.swift:176-196`, the `sky` scene uses `try?` around matte generation and simply continues with its global exposure when generation fails. It exits on a refused matte upload but not on generation failure. A requested `--screenshot --scene sky` can therefore write a plausible PNG with no sky selection. This is a posed scene, not one of the three asserted `check-screens.py` gates. | Fail this scene when matte generation throws, as it already does for upload refusal. Exercise one no-sky or readback-failure input and require a nonzero exit. |

## Useful coverage and limits

The batch probe genuinely exercises one engine across GUI batch export, restored edit/history, pending-save refusal and retry, cancellation between two jobs, malformed saved edits, missing mattes, failed restore, and an AppKit Escape event. It compares rendered export bytes for restored brush/matte and XML alias cases (`app/BatchExportProbe.swift:79-91,99-125,129-150,255-283,289-355`). The normal viewport runner returns nonzero on recorded failures (`app/ViewportTests.swift:11-27,250-252`); the scenario runner defaults to at least one assertion and fails unknown verbs (`app/Scenario.swift:292,304-363,407-414`). The screenshot checks use the actual AppKit menu and a stable two-failure-frame comparison, while their comments correctly limit menu proof to presence (`app/Screenshot+Checks.swift:75-166,183-284`). These are meaningful checks. They do not demonstrate physical gestures, a 42 MP batch, full-resolution RAM, real disk faults, or VoiceOver behavior.
