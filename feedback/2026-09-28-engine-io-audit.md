# Engine I/O audit — 2026-09-28

Read-only source review of local `40618db`, then revalidation of changed ImageWriter, C facade, and Engine export code after upstream `bda5847` merged into worktree `c31c964`. The export restoration change was made concurrently and is outside this audit's verdict. No RAW decode, GPU run, build, or memory stress was performed. Sizes below follow allocation expressions; they are not measured footprints. Pipeline cache and Swift/mask internals are covered by the other audits.

| Rank | Finding and trigger | Smallest useful fix | Coverage |
|---|---|---|---|
| **P1 — data loss** | **HDR output collision is checked before a long merge, then overwritten at rename.** `HdrMerge::run` refuses a pre-existing path at `HdrMerge.cpp:217–221`, but `DngWriter.cpp:299–325` writes `path + ".part"` and calls `std::rename(partial, path)`. If another file arrives at `path` during decode/align/write, POSIX rename replaces it. A stale or concurrent `.part` is also truncated because the temporary name is fixed. | Reserve a unique sibling temp file exclusively, then install it with a no-replace operation; fail and remove only this run's temp on collision. | `tests_hdr_merge.cpp:150–153` checks an **already existing** output; it does not race a late arrival or shared `.part`. |
| **P1 — failed open changes export source** | `Engine.cpp:32–46` sets `sourcePath_`, lens fields, and choice before graph construction. The new graph can throw at `:70`, and `:68–69` expressly promises the old image survives. After that failure, `exportImage` takes metadata from the *new* `sourcePath_` (`:409–417`) while rendering the *old* image. The same mixed state can follow an exception in metadata lookup or `reload` (`:61–64`). | Stage new path, metadata, lens profile, and graph; commit them together after successful construction/reload. | Existing linear-DNG open tests cover success (`tests_dng.cpp:489+`); no failed-second-open then export assertion found. |
| **P1 — failed standard export may leave damaged output** | `ImageWriter.mm:480–491` creates an ImageIO destination directly at the requested path and throws if finalize fails. There is no sibling temp or cleanup/rename. A disk-full or encoder failure can therefore leave an incomplete file; writing over an existing path may damage the old file. This is an exposure of the code path, not a reproduced disk failure. | Encode to a unique sibling temp, finalize, then replace/rename according to the caller's overwrite policy; remove temp on failure. | `tests_io.cpp:475+` checks successful formats/metadata/depth/sharpening, not failed finalize or preservation of an existing destination. The merged watermark path still uses this writer. |
| **P2 — transient RAM on each open** | `RawImage.cpp:358–361` copies the entire Bayer sample vector into `out` and then overwrites it with the small preview allocation; `:407–410` repeats this for the larger fp16 RGBA linear source. At 42 MP the avoidable copy is about 84 MB for Bayer or 337 MB for linear, in addition to the source, LibRaw's unpacked buffer, and both graph allocations. | Copy only scalar metadata, then allocate the decimated vector directly. | `tests_color.cpp:279+` covers Bayer decimation results; no peak allocation/failed allocation check found. |
| **P2 — HDR RAM scales with bracket length** | `HdrMerge.cpp:225–271` retains every full-size float RGB frame (12 bytes/pixel/frame); `Merge.cpp:168–172` allocates another full-size float RGB result. At 42 MP, three retained frames plus output are about **2.03 GB decimal** before LibRaw's current unpacked frame, GPU intermediates, readback (`MergeRender.cpp:72–83`, ~337 MB fp16 RGBA), and writer buffers. Memory is bounded only by the caller's frame count; no count or budget gate exists. | Apply a device/memory budget before decode, or stream/tile the merge if larger brackets are a product requirement. Measure a representative bracket before choosing a redesign. | `tests_hdr_merge.cpp:78–159` merges three small synthetic frames; no 42 MP or long-stack memory check. |
| **P2 — cancellation latency** | `HdrMerge.cpp:318–351` checks cancellation once before the full `merge()` pass and once before preview/write. `Merge.cpp:174–251` and `DngWriter.cpp:306–318` do not poll. A request during those stages waits for an entire full-resolution merge or DNG write and may still finish with a valid file. `HdrMerge.h:16–17` promises only stage-boundary polling, so this is a responsiveness gap rather than an atomicity violation. | Poll the existing atomic between merge rows and writer rows; clean up this run's temp on cancellation. | `tests_hdr_merge.cpp:162–213` races a cancellation but accepts either full output or no output; it does not bound response time. |
| **P3 — avoidable repeated work** | HDR reads each source twice: `HdrMerge.cpp:231` calls `readInfo` and `:234` calls `decode`; ordinary open does the same at `Engine.cpp:32–37`. Each creates a fresh LibRaw and opens the file (`RawImage.cpp:37–46`, `:157–165`). Alignment also recomputes the reference proxy and ORB features for every non-reference frame (`HdrMerge.cpp:293–301`, `Align.cpp:129–139`). | Return needed EXIF/lens fields with decode and prepare reference alignment once per bracket. Do this only if profiling shows I/O or ORB is material. | Successful decode/merge paths exist; no paired timings for these repetitions in this review. |

**Exception boundary:** The main status APIs use `guard()` (`CApi.cpp:35–49`), but its `noexcept` catch path calls `Engine::setError(std::string)` (`Engine.h:186`), which can allocate and throw during an out-of-memory error, terminating the process. `orion_lens_name_count/at` initialize an allocating static outside `guard()` (`CApi.cpp:785–803`). These are low-frequency but definite exceptions to the file's “nothing throws past this file” contract. Keep the error fallback allocation-free and guard static initialization. No fault-injection coverage found. The merged facade adds watermark option forwarding but does not change these paths.

**No additional claim:** The DNG writer already stages row writes and normally renames only a complete file; `tests_hdr_merge.cpp:162–213` covers that ordinary cancellation invariant. `ImageWriter.mm` converts at 16-bit depth after resizing and its tests cover that regression. Runtime latency, actual peak memory, disk-full behavior, and collision races remain unmeasured here.
