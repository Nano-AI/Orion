# Canvas and geometry source audit — 2026-09-28

Source-only review of the ten files listed below. No product or planning code changed; no build, test, GPU render, app launch, physical gesture, or memory measurement was run. These are source-supported paths to reproduce, not claims about observed pixels or RSS. The active batch story owns implementation; findings here queue separate work. The earlier masking and desktop audits already own raster-mask lifecycle, brush cursor warping, and main-thread batch work.

| Rank | Finding, trigger, and evidence | Minimum useful repro / fix |
|---|---|---|
| **P1 — spot history loses a dragged source** | A new spot is recorded **before** its source is dragged (`app/SpotOverlay.swift:133–147`, `app/Engine+Spots.swift:54–57`). The placement path expressly skips `commitSpotEdit` on release (`SpotOverlay.swift:161–164`), while `moveSpot` only renders (`Engine+Spots.swift:93–107`). `EditHistory.record` snapshots the passed state, and redo restores that snapshot (`app/EditHistory.swift:56–95`, `app/Engine.swift:695–701`). Thus a press-and-drag source can render and autosave at its dragged location, but undo then redo restores the *automatic* source position captured at press. A later unrelated history entry also leaves the history panel's Spot entry at that original position. | Place a spot, drag its source away, undo, redo; assert the source returns to the dragged position. Record final placement on release by replacing/updating its initial entry, while preserving one undo step and the existing distinct "Move spot" label for later drags. A pure state/history check suffices; pixel output can be checked separately. |
| **P2 — Compare reintroduces minification aliasing** | `Renderer.draw` selects the mipmapped `CanvasReduce` texture only when `engine.compareSplit >= 0.999` (`app/ImageCanvas.swift:443–454`). At fit scale below 0.5, any active split samples both original and edited full-resolution, one-level textures with `minFilter = .linear` (`:167–183`, `:491–494`). That is only a 2×2 tap regardless of the reduction ratio; decision #213 measured this exact sampling path as visibly noisier before reduction was added. The intentional reason in the comment is common UVs for the two textures, but the current branch removes the reduction from **both** sides whenever Compare is active. The existing `testCanvasReductionAverages` checks `CanvasReduce.reduced` alone (`app/ViewportTests+Canvas.swift:371–462`); the offscreen `CanvasBlit.composite` uses a native-size target (`app/CanvasBlit.swift:184–239`) and cannot exercise a fitted window. | At a 4× or greater fit reduction, present a one-pixel checkerboard through the real Compare draw path and check each side averages to gray. Build matched reduced originals and edited textures with the same valid rectangle/UV mapping, then compare them. Measure the added texture cost before choosing a cache lifetime; this audit makes no measured display claim. |
| **P2 — settled histogram expands a full frame into large CPU buffers** | `Engine.scheduleHistogram` runs after each successful full render, debounced 160 ms (`app/Engine+Render.swift:265–302`, `:356–366`). The histogram call allocates only 3×128 counters in Swift (`:188–196`), but native `Engine::histogram` calls `readOutputFloat(w,h)` for the **entire** output before sampling every 31st pixel (`engine/src/Engine.cpp:328–353`). `readOutputFloat` allocates four `float` channels per pixel *plus* a four-byte-per-pixel download buffer for the narrow screen path (`Engine.cpp:445–458`). Arithmetic transient payload is about **480 MB decimal at 24 MP** and **840 MB at 42 MP**, before GPU staging, allocator overhead, and the rest of the editor. This corrects the `~96 MB at 24 MP` comment at `Engine+Render.swift:356`, which counts only downloaded bytes. It is a source-level allocation calculation, not measured peak RSS. The separate desktop audit already notes the synchronous main-actor histogram; this finding is the hidden expansion despite 1-in-31 sampling. | Instrument peak live allocations during a settled 42 MP edit. Bin directly from the downloaded narrow bytes while walking stride 31, or downsample on GPU first; keep the same histogram bins as an invariant on a small known image. Avoid allocating float RGBA for pixels the loop never reads. |
| **P2 — clipping flags include unclipped tones** | `Histogram.clipped` treats the first/last of 128 bins as the share "at black"/"at white" (`app/Histogram.swift:84–112`, `:198–213`, `app/Engine+Render.swift:188–195`). The engine maps any value in `[0, 1/128)` to the first and any value in `[127/128, 1]` to the last (`engine/src/Engine.cpp:346–351`). A uniform 8-bit frame at value **1** therefore reports 100% shadow clipping; value **254** reports 100% highlight clipping, although neither reaches the 0/255 display endpoints. The flag lights above 0.1% (`Histogram.swift:31–36`). This is a bin-definition inference from the code, not an observed UI frame. | Feed uniform 1 and 254 display-code frames through the histogram and assert both flags remain off; 0 and 255 should light. Count exact endpoint samples separately from the 128 shape bins, or label the flags honestly as near-black/near-white with an intentional range. |

Other traced paths: the ordinary canvas samples `Engine.displayTexture`, with preview dimensions passed explicitly (`ImageCanvas.swift:403–409`, `:418–450`); a render generation and source identity key the temporary mip chain (`:225–250`), and the reduction uses one GPU command buffer with the halve and mip commands ordered (`CanvasReduce.swift:79–117`). The viewport's anchor zoom formula and final clamp (`Viewport.swift:55–69`, `:113–119`) agree with the blit's visible-fraction transform (`CanvasBlit.swift:133–172`). No new defect was established in those paths by inspection. `MatteGeometry`'s quarter-turn and size rules are already exercised by viewport tests; no new independent issue was established there. `CurveMath` names the Fritsch–Carlson source in `research/tone-and-local-contrast.md` and has an engine comparison test; no new divergence was established. `Engine+Geometry`'s fallback identity map on facade failure (`:114–123`) deserves a failure-path test, but this audit did not establish a reachable wrong-edit case. `Engine+Spots` has one conversion path for placement/movement; the history gap above is the concrete lifecycle issue.
