| **P1 — fixed writable test outputs** | `apps/tests/tests_watermark.cpp:70-79,127-128,147,172` writes eight predictable `/tmp/orion-wm-*.png` paths. The test passes them to `writeImage`, whose `engine/src/util/ImageWriter.mm:472-493` creates and finalizes an ImageIO destination at the supplied URL, with no reservation or ownership check. | A test run may replace an existing file at one of those names and concurrent test runs may clobber each other's fixtures. These paths also persist after the process exits. No collision was induced here. | Use a private temporary directory created with `mkdtemp` (or the existing test helper if one is introduced elsewhere), put the eight files beneath it, and remove only that directory after the test. A single pre-existing sentinel at one fixed path demonstrates the current risk without touching product code. |
| **P2 — decode failure can turn a watermark subcheck green** | `apps/tests/tests_watermark.cpp:150-157,175-181` enters its resized and Display P3 assertions only when `write(...) && decode16(...)` succeeds. `write` reports failure, but `decode16` (`apps/tests/tests_io.cpp:183-216`) returns `false` without reporting. If a written file cannot be decoded, the entire size/coverage or P3 neutrality check contributes **zero failed checks**. The initial plain/marked decode at `tests_watermark.cpp:85-89` does report, so this is specific to the later two blocks. | A broken encoded file can leave the watermark test exit status green on those branches. `encodedSize > 0` in the resize block does not prove the file can be read back. | Report a failed decode explicitly before guarding pixel access, as the initial block already does. One corrupted file or failing decoder return should make each branch red. |
| **P2 — NaN pixels can pass max-error GPU oracles** | `apps/tests/tests_grade.cpp:360-366` starts `worstIdentity = 0` and folds `std::max(worstIdentity, abs(out-input))`, then checks `worstIdentity < 1e-3`. A NaN half-float output makes the candidate NaN; `std::max` keeps the finite accumulator, so even a NaN-filled frame can satisfy the identity check. The same pattern occurs in `tests_perspective.cpp:258-275`, `tests_fusion.cpp:323-344`, `tests_highlights.cpp:360-374`, and many reductions in `tests_effects.cpp` and `tests_tone.cpp`. In `tests_grain.cpp:224-238`, `abs(NaN - want) > tolerance` is also false and increments no failure count. | The binary reads real GPU textures but can report a small worst error despite nonfinite pixels. It could miss a poisoned render at exactly the boundary these tests are meant to catch. This does not imply the current shaders produce NaNs. | In each reduction that claims a finite error, set a shared `finite` flag from `std::isfinite` before `std::max`, and require it in the final `report`. A single NaN injected in the downloaded vector is the smallest runnable oracle check. |
