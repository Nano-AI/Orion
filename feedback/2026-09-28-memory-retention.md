# Inactive GPU caches retained after filters were disabled

Before the fix, disabling a node left its `ownedOutputs` on the node, and the pool retained its idle textures. The fix returns disabled outputs and shrinks idle pool storage at graph transitions. In a reduced `_PIC8220.ARW` session (1992×1330 full graph plus 498×332 preview), a **controlled no-shrink mutation of the final implementation** held 903.1 MiB of texture payload after filters were turned off and after reopen. With transition-time pool shrink, the same states held 303.5 MiB. This comparison isolates the shrink step; it is not a benchmark of the original code. Active filters still held 903.1 MiB. The process footprint after cycle 3 reopen was 1257.5 MiB without shrink and 816.4 MiB with it; allocator and Metal behavior make footprint a separate, noisier measure.

The first fix also cleared the terminal output when a 16-bit export or size estimate restored narrow format. Both paths now render the screen frame before returning. GPU tests compare the actual downloaded screen bytes at that boundary. The premerge suite passed 1,128 checks; disabling shrink alone made the three new residency assertions fail. The integrated postmerge suite passed 1,143 checks (see `2026-09-28-verification.md`).

This is a reduced-resolution retention measurement, not a full-resolution capacity claim. Active-filter peak footprint was about 1.26 GiB in both runs. The harness caps the developed frame at 3 MP after decoding, so decoding an exceptionally large source can still have a high transient cost. No full-resolution stress run was repeated under the session memory restraint.
