# Independent layers — decision #75 stage 2, ROADMAP's decomposition.
#
# Reported repeatedly: "I should be able to colour grade and do all of that
# editing on a different mask", and "one master mask by default, and I can
# apply each and every edit mask by mask."
#
# A layer is a **run of consecutive mask components**. Rows in one run fold
# together into a single coverage and share one set of adjustments; a break
# starts a new coverage with its own. That is why there is no separate layer
# list: the row list already is one.
#
# ⚠ The load-bearing property is independence — two layers over different parts
# of the picture, each with its own grade, and neither reaching the other.

open samples/_PIC8220.ARW
set exposure 2.6

# ⚠ Baselines first. The claim is that two layers move in **opposite
# directions at once**, and that is a statement about each region against its
# own unmasked value — not against a threshold picked by eye. The first draft
# asserted `left < 0.35` and failed at 0.42 against a working stack.
measure 0.19,0.47,0.06,0.06 leftBase
measure 0.75,0.47,0.06,0.06 rightBase

# Layer 1: a radial over the left.
mask radial
set maskCentreX 0.22
set maskCentreY 0.50
set maskRadiusX 0.15
set maskRadiusY 0.15
set localExposure -2.5

# Layer 2: a radial over the right. Its own row *is* its own break since
# #197 - a new mask starts its own layer.
maskadd radial
set maskCentreX 0.78
set maskCentreY 0.50
set maskRadiusX 0.15
set maskRadiusY 0.15
set localExposure 1.5

measure 0.19,0.47,0.06,0.06 left
measure 0.75,0.47,0.06,0.06 right
measure 0.48,0.10,0.06,0.06 between

# ⚠ Opposite signs at the same time. One shared adjustment cannot do this: the
# left is pulled down two and a half stops while the right is lifted one and a
# half, in one render.
expect left < leftBase
expect right > rightBase

# ── Each layer's grade reaches only its own coverage ────────────────────
masklayer 0
set localSaturation -1.0
measure 0.19,0.47,0.06,0.06 leftDesat
measure 0.75,0.47,0.06,0.06 rightUntouched
expect leftDesat != left
expect rightUntouched == right

# ── And the other way ───────────────────────────────────────────────────
masklayer 1
set localWarmth 1.0
measure 0.75,0.47,0.06,0.06 rightWarm
measure 0.19,0.47,0.06,0.06 leftUntouched
expect rightWarm != rightUntouched
expect leftUntouched == leftDesat

# ⚠ And nothing between them moved at any point — two layers must not add up to
# a global adjustment.
measure 0.48,0.10,0.06,0.06 betweenAfter
expect betweenAfter == between

# ── ⚠ A row that begins a layer cannot be subtracted into nothing ───────
#
# Found by looking at the panel: row 2 started a layer and still showed an "add"
# op. The op is not merely decorative there — the fold starts from zero, so
# subtract gives 0·(1−α) and intersect gives 0·α, and the layer comes out empty
# whatever is painted into it.
#
# Splitting a row that already carried Subtract would therefore have silently
# emptied its layer, which looks exactly like a mask placed wrong. The engine
# forces add on any row that begins a layer.

open samples/_PIC8220.ARW
set exposure 2.6
mask radial
set maskCentreX 0.22
set maskCentreY 0.50
set maskRadiusX 0.15
set maskRadiusY 0.15

maskadd radial
# Folded back into layer 1 - a new mask starts its own layer since #197, and
# this block needs the row *inside* the fold for its subtract to mean anything.
masklink 1
set maskCentreX 0.78
set maskCentreY 0.50
set maskRadiusX 0.15
set maskRadiusY 0.15
# Row 2 subtracts while it is still part of layer 1.
set maskCompose 1
set localExposure -2.5
measure 0.75,0.47,0.06,0.06 subtracted

# Now split it into its own layer and give that layer the same exposure. The
# subtract must stop applying, or the layer renders nothing.
masksplit 1
masklayer 1
set localExposure -2.5
measure 0.75,0.47,0.06,0.06 ownLayer
expect ownLayer != subtracted
