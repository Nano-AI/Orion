# Arming the preview graph changes what you SEE during a gesture. It must never
# change what you GET after one.
#
# Every gesture on the picture now arms degrade-then-refine (decision #84), so a
# drag renders the quarter-linear preview graph and `endInteraction` renders the
# full graph once when the hand stops. That is safe only if the settled picture
# is the same either way.
#
# ⚠ This is the check the four gestures added on 2026-08-01 were held back for.
# Crop is the reason: its rectangle *is* the geometry being changed, and this
# project has already shipped one bug of exactly this shape — the compare split
# sampling two differently-sized textures through one set of UVs. A gesture that
# left the canvas on the preview, or that computed its geometry against the
# texture rather than the picture, would look plausible and be wrong.
#
# The pattern below is the same three steps for each control:
#   1. drive it with the preview graph OFF, measure the settled picture
#   2. reset, drive it identically with the preview graph ON, measure again
#   3. expect the two measurements to be equal
#
# `expect a == b` compares mean luma AND mean saturation, because one number per
# frame is too weak a signature to say two renders are the same picture.

open samples/_PIC8220.ARW

# ── Crop, the riskiest one ────────────────────────────────────────────────
crop 0.15 0.2 0.6 0.55
measure 0.25,0.25,0.5,0.5 crop_unarmed
open samples/_PIC8220.ARW
interact on
crop 0.15 0.2 0.6 0.55
interact off
measure 0.25,0.25,0.5,0.5 crop_armed
expect crop_armed == crop_unarmed

# ── The tone curve ────────────────────────────────────────────────────────
open samples/_PIC8220.ARW
drag contrast 1.0 1.6 12
measure 0.25,0.25,0.5,0.5 curve_unarmed

open samples/_PIC8220.ARW
interact on
drag contrast 1.0 1.6 12
interact off
measure 0.25,0.25,0.5,0.5 curve_armed
expect curve_armed == curve_unarmed
